# `mall-front` Project Rules (고객용 도서 쇼핑몰 프론트)

이 디렉터리는 **고객이 도서를 탐색·구매하고 배송 상태를 확인하는 쇼핑몰 사이트(`mall-front`)** 프로젝트다. 루트 `../AGENTS.md` 규칙과 함께 아래 세부 규칙을 준수한다.

---

## 1. 데이터 접근 및 API 통신 원칙 (절대 경계)

1. **DB 직접 연결 금지**: 이 프로젝트 내부에는 어떠한 데이터베이스 드라이버, JPA/ORM 설정, SQL 쿼리도 존재해서는 안 된다.
2. **단일 API 게이트웨이 계층**:
   - `mall-admin`의 Store API(`/api/v1/store/**`) 호출은 반드시 중앙화된 API 클라이언트 모듈을 통해서만 수행한다.
   - API 기본 주소(`MALL_ADMIN_API_BASE_URL`)는 환경변수로 주입받으며 코드에 포트나 호스트를 하드코딩하지 않는다.
   - API 요청/응답 타입은 `../docs/specs/store-api-contract.md` 및 `mall-admin`의 OpenAPI 스펙과 항상 1:1로 동기화한다.
3. **표준 에러 처리**: `mall-admin`이 반환하는 RFC 9457 `ProblemDetail` 응답(필드 검증 오류, 재고 부족, 인증 만료 등)을 공통 인터셉터에서 파싱하여 사용자 친화적인 한국어 안내 메시지로 표시한다.

---

## 2. 자체 회원가입 및 클라이언트 보안 규칙

1. **자체 회원가입/로그인 플로우**:
   - 외부 소셜 로그인 강제 없이 홈페이지 자체 회원가입(아이디/이메일 중복 확인, 비밀번호 강도 실시간 검증, 필수 약관 및 개인정보 수집·이용 동의 체크)을 완결성 있게 제공한다.
   - 로그인 실패 시 계정 존재 여부를 유추할 수 없는 일관된 안내 메시지("아이디 또는 비밀번호를 확인해주세요.")를 노출한다.
2. **브라우저 내 개인정보/토큰 보호**:
   - Access Token/인증 쿠키는 XSS 탈취 위험을 최소화하도록 `HttpOnly; Secure; SameSite` 쿠키 또는 메모리 기반 토큰 전략(`docs/adr/000-pending-decisions.md` 확정안 기준)을 따르며, 민감한 고객 개인정보(전체 주소, 연락처, 이메일 원문 등)를 브라우저 `localStorage`나 `sessionStorage`에 영속 저장하지 않는다.
   - 로그아웃 시 클라이언트 인증 상태와 캐시된 마이페이지/주문 데이터를 즉시 초기화한다.

---

## 3. 도서 쇼핑몰 및 배송 UX 핵심 요구사항 (YES24 · 알라딘 벤치마킹)

모든 화면의 상세 IA와 기능 구성은 반드시 `../docs/specs/bookstore-benchmark-spec.md`를 따른다.

1. **서점 표준 탐색 & 검색 IA**:
   - 다단계 분야별 카테고리, **베스트셀러 랭킹**, **신간도서**, **오늘의 책(MD 추천)** 큐레이션 섹션을 제공한다.
   - 검색창은 `통합검색 / 도서명 / 저자·역자 / 출판사 / ISBN` 조건 필터를 지원한다.
2. **서점 특화 목록 & 도서 상세 구성**:
   - 도서 목록/검색 결과는 **요약 리스트형(표지 + 서지정보 + 도서정가제 할인가/적립금 + 출고예정일 배지 + 다중 체크 일괄 장바구니 담기)**과 **표지 그리드형** 전환을 지원한다 (`OUT_OF_STOCK`/`DISCONTINUED` 도서는 구매 버튼 비활성화).
   - 도서 상세 화면은 상단 구매/출고예정일 안내 패널과 하단 Sticky 탭(`품목정보` · `책소개` · `목차` · `저자소개` · `독자리뷰/한줄평` · `배송/반품안내`)으로 구성한다.
3. **장바구니 · 보관함(찜) · 주문/배송 조회**:
   - 장바구니에서 선택 상품 금액 합산 및 **"무료배송까지 남은 금액" 실시간 안내 게이지**를 제공하고, 관심 도서 **보관함(`Wishlist`)** 연동을 지원한다.
   - 마이페이지에서 주문 단계별 카운트 요약(`결제완료` → `상품준비중` → `배송중` → `배송완료`)과 운송장 번호, 택배사 단계별 배송 추적 타임라인을 직관적으로 확인할 수 있어야 한다.

---

## 4. 브랜드 컬러(`#918a7d`) 및 100% 반응형 UI 불변식

1. **메인 컬러 `#918a7d` 토큰 강제**:
   - 모든 버튼, 강조 배지, 액티브 상태, 포커스 링, 헤더/네비게이션 포인트는 반드시 `../docs/specs/ui-design-system.md`에 정의된 **`#918a7d`** 기반 디자인 토큰(`--color-brand-50` ~ `--color-brand-900`)을 사용한다.
   - CSS 프레임워크의 기본 파란색/보라색(`blue`, `indigo`, `violet`, `purple`) 유틸리티를 습관적으로 사용하는 것을 엄격히 금지한다.
2. **전 구간 100% 반응형 및 PC ↔ 모바일 레이아웃 구조 전환 (Zero Horizontal Overflow)**:
   - 모든 화면(메인, 도서목록/검색, 도서상세, 회원가입/로그인, 장바구니, 주문서, 마이페이지/배송조회, 모달/드로어)은 **`320px`(소형 모바일) ~ `768px`(태블릿) ~ `1440px+`(PC)** 전 해상도에서 레이아웃 깨짐 및 가로 스크롤(`overflow-x`) 없이 동작해야 한다.
   - 단순 폭 축소가 아니라 **PC와 모바일에 맞게 레이아웃 구조 자체를 전환**한다 (`../docs/specs/ui-design-system.md` 참조):
     - **App Shell**: PC 풀 헤더 + 수평 GNB 바 ↔ 모바일 컴팩트 앱바 + 슬라이드 카테고리 드로어 + 하단 탭 네비게이션(상세·장바구니·주문서는 하단 Sticky 액션바)
     - **목록/상세/주문**: PC 좌측 필터 사이드바 및 우측 Sticky 결제 요약 2단 분할 ↔ 모바일 상단 필터 칩/바텀시트 + 1열 구조화 카드 리스트 + 세로형 배송 추적 타임라인
   - 모바일 터치 타깃 최소 `44x44px`, 입력창 폰트 최소 `16px`, 도서 표지 `aspect-ratio: 3 / 4` 유동 컨테이너를 보장한다.
